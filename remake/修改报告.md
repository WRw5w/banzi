# 《算法板子》重修报告

## 0. 重修结论

当前《合订本.pdf》不再继续小修小补，而是重构为两本相互独立的手册：

1. **第一本：区域赛现场速查版**
   - 面向比赛现场翻阅。
   - 只保留“区域赛铜牌以上、银牌档常见、值得准备成板子”的内容。
   - 重点是定位快、代码能独立复制、接口明确、样例能验证。
   - **错题本放在第一本最后，作为压缩后的附录。**

2. **第二本：详细学习与验证版**
   - 面向赛前学习、理解原理、验证模板。
   - 可以比第一本详细，但仍然只收录本次重构范围内的算法。
   - 不再把超高难算法作为“以后可能用到”的百科式附录。

本次重修的目标不是把手册做成算法大全，而是让大约 1700–1800 CF 水平的使用者在区域赛遇到银牌档题时能够：

```text
从题面关键词定位算法
→ 找到一份完整模板
→ 知道每个接口如何调用
→ 用样例和边界数据确认没有抄错
→ 根据题目约束修改数组、类型和答案维护方式
```

## 1. 重构原则

### 1.1 现场优先，而不是内容优先

每一页都必须回答以下问题：

- 这是什么题型？
- 什么时候可以使用？
- 什么时候不能使用？
- 代码的入口函数是什么？
- 数组和下标分别表示什么？
- 多测需要清空什么？
- 复杂度和内存是多少？
- 如何用一个完整例题确认模板可用？

如果某段内容不能帮助现场判断、复制、修改或排错，就不进入第一本。

### 1.2 一个算法只保留一个主模板

同一算法不得在多个章节重复出现完整代码。

允许存在：

- 一个主模板；
- 一个变体模板；
- 其他章节用“见第 X 页”或关键词索引跳转。

禁止继续出现以下形式：

- 第七章写一次线段树，第八章再完整写一次；
- 第十一章写一遍图论，第十二章再重新写一遍；
- 第九章写 KMP，第十章再完整复制 KMP；
- 同一算法在基础、补充、错题本中各复制一份不同版本。

### 1.3 统一以 `muban.cpp` 为代码地基

不额外维护独立头文件，直接以 [muban.cpp](muban.cpp) 作为整本手册唯一的基础模板。
每份算法板子都从这份地基复制，再追加自己的结构体、数组、函数和 `solve()` 调用。

`muban.cpp` 统一提供：

- `#include <bits/stdc++.h>`；
- `using namespace std`；
- `#define int long long`；
- `#define endl '\n'`；
- `i64`、`i128` 类型别名；
- `inf`、`N`、`eps` 基础常量。

本项目默认优先使用 `long long`，因为竞赛中整数溢出 `int` 的风险远高于溢出 `long long`。
本次重构不专门处理 `unsigned` 类型；确实需要无符号整数的题目另行标注，不作为 `muban.cpp` 的默认能力。

算法卡片不再重复粘贴整套基础代码，而是只声明相对于 `muban.cpp` 的额外依赖：

- 额外的类型或结构体；
- 额外常量和节点池大小；
- 全局数组或容器；
- 初始化函数；
- 主调用方式；
- 输入输出接口。

“代码独立可用”的含义调整为：将 `muban.cpp` 与该算法卡片的追加代码放在同一个源文件后即可编译运行。
不能依赖其他算法章节中偶然出现的 `MAXN`、`INF`、`G` 或初始化逻辑；如果需要覆盖
`muban.cpp` 中的 `N`、`inf` 或 `eps`，必须在卡片开头明确写出覆盖规则。

### 1.4 解释必须服务于代码

详细解释只保留对使用有帮助的部分：

- 状态定义；
- 核心不变量；
- 为什么转移正确；
- 复杂度；
- 容易抄错的地方；
- 如何改成常见变体。

删除泛泛的历史介绍、重复定义和与代码调用无关的长篇科普。

### 1.5 高难算法没有完整验证就不能作为可抄板子

任何模板在进入第一本之前必须满足：

- 至少有一个完整可编译程序；
- 至少有一个正式题面；
- 至少有一组完整输入输出；
- 至少有四组边界测试；
- 明确测试通过的编译标准和内存假设。

没有经过验证的内容只能删掉，不能用“了解”“备用模板”“调用示例”保留在现场版中。

### 1.6 明确取舍，不追求算法大全

本次重构不收录以下内容：

- Segment Tree Beats；
- Link-Cut Tree；
- 动态 DP 与矩阵线段树；
- Steiner 树状压 DP；
- 生成函数高级优化；
- 扩展 BSGS；
- Tonelli–Shanks、Cipolla 等二次剩余高级变体；
- PAM 的复杂动态统计；
- 多字符串 SAM / 动态 AC 自动机；
- 半平面交的复杂工程变体；
- 超出当前区域赛银牌准备范围的高级几何；
- 仅为展示知识面而加入的 2300–2500 分算法。

这些内容不是本阶段的目标。它们既不放进第一本，也不放进第二本的附录。后续真正遇到需求时，再单独制作专题卡片。

## 2. 两本手册的最终定位

## 2.1 第一本：区域赛现场速查版

建议控制在 **100–140 页**，包括错题附录。

实际目录采用“少而稳定”的七章结构，避免为了凑分类把同一类模板拆散：

第一本不放长篇证明，不放算法历史，不放无关扩展。它的任务是比赛翻阅，不是系统教材。

建议控制在 **180–260 页**。

## 5. 关键代码规范

### 5.1 统一使用全局 `#define int long long`

`muban.cpp` 统一使用：

```cpp
using i64 = long long;
using i128 = __int128_t;
#define int long long
// 别把这个改成具体的数,比赛的时候谁有时间给你重写
const int inf = 2e18+10;
const int N = 1e6 + 10;
const double eps = 1e-8;
```

本项目默认不考虑 `unsigned` 类型。所有普通整数统一使用 `int`，由宏映射为
`long long`；需要更大中间结果时使用 `i128`。

使用该宏时必须遵守：

- 主函数写 `signed main()`；
- 位移中的常数使用 `1LL`；
- 不使用依赖 32 位 `int` 宽度的接口；
- 算法卡片中明确数组、节点池和内存规模；
- 不在局部再次定义相互冲突的 `int`、`inf` 或同名宏。



### 5.2 所有大结构提供初始化函数

必须统一提供：

```cpp
void init();
```

或者构造函数初始化，并在卡片中说明：

- 节点池是否清空；
- 图是否清空；
- `last/tot/timestamp` 是否重置；
- 多次调用是否安全；
- `build()` 是否只能执行一次。

### 5.3 内存必须按约束开

删除统一的 `N = 1e6 + 10` 习惯。

每个模板必须写清楚：

```text
若字符串总长度为 S，AC/SAM/PAM 节点池按 S 或 2S 开。
若 n ≤ 2e5，线段树按 4n 开。
若图有 m 条边，无向图边池按 2m 开。
```

### 5.4 代码依赖必须在卡片内完整出现

每页代码不能依赖前面章节的隐藏定义。至少要明确：

- `#include`;
- `using`;
- `constexpr`;
- 全局结构；
- 函数声明；
- 输入输出接口；
- 初始化。

## 10. 最终原则

本次重修必须坚持以下底线：

1. **不追求算法数量，追求现场可用。**
2. **不保留未验证的“看起来很厉害”的模板。**
3. **不让同一算法在多个章节重复出现。**
4. **高难算法没有完整题面和 I/O，就不算完成。**
5. **每个模板都必须说明初始化、内存、复杂度和调用方式。**
6. **第一本服务比赛，第二本服务学习。**
7. **错题本只保留能在比赛中帮助排错的最小信息。**
8. **本阶段不收录超出目标范围的高级算法。**
